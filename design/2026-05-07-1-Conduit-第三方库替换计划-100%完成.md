> **创建日期**：2026-05-07
> **作者**：调研由 AI 资深工程协作完成,user 拍板。
> **背景**:`netdev` 替换 `local_ip_address`/`vpn_detect` 启发式后,继续推进剩余高频手写代码的"上游可靠 crate"替换,目的是把"维护表面"压缩到只剩业务逻辑。
> **范围**:server-app + client-app + crates/conduit-core 三处代码,**不动**测试用例外的 UI/产品行为,只换实现。

## 一、整体决策

## 二、执行顺序与原则

按"**先简单再难、先 control_api 再 forward proxy**"的策略,分阶段提交:

1. **阶段 1: 内部去重**(P1-3) — 不引新 crate,2 分钟工作,先把 `epoch_secs` 提到 `conduit-core::time`
2. **阶段 2: percent-encoding**(P0-2) — 引 1 个零依赖 crate,删 30 行
3. **阶段 3: control_api 改 axum**(P0-A) — 双端各 ~200 行换 axum/tower,改完单跑 cargo test 验证
4. **阶段 4: security-framework Authorization**(P1-6) — macOS FFI 收敛
5. **阶段 5: forward proxy 改 hyper**(P0-B) — 最重的一项,放最后,改完真机跑 CONNECT/PAC/绝对 URI 三类流量回归

每阶段完成后:
- `cargo test -p conduit-server -p conduit-client --lib --no-fail-fast` 全过
- `cargo clippy -p conduit-server -p conduit-client -- -D warnings` 无 warning
- `pnpm -r lint` 全过
- 阶段 3、5 完成后还要手动跑一次 `cargo build --release` 确保产物可启动
- 阶段 5 完成后,手动跑 server-app + client-app 真机连一次,验证 SSE / CONNECT / PAC 能用

每阶段建议**单独 commit**,出问题可分阶段回滚。

## 三、详细计划

### 阶段 1: P1-3 — 把 `epoch_secs` 去重到 `conduit-core::time`

**改动**:
1. `crates/conduit-core/src/lib.rs` 加 `pub mod time;`
2. 新增 `crates/conduit-core/src/time.rs`,内容仅:
   ```rust
   use std::time::{SystemTime, UNIX_EPOCH};

   pub fn epoch_secs() -> f64 {
       SystemTime::now()
           .duration_since(UNIX_EPOCH)
           .map(|d| d.as_secs_f64())
           .unwrap_or(0.0)
   }
   ```
3. 4 处删除本地 `fn epoch_secs`,改 `use conduit_core::time::epoch_secs;`:
   - `server-app/src-tauri/src/proxy/session.rs`
   - `server-app/src-tauri/src/proxy/control_api.rs`
   - `server-app/src-tauri/src/proxy/core.rs`
   - `server-app/src-tauri/src/proxy/traffic_emitter.rs`

**验证**: `cargo test -p conduit-server -p conduit-core --lib`

**改动**:
1. `Cargo.toml`(workspace) 加: `percent-encoding = "2"`
2. `server-app/src-tauri/Cargo.toml` 加 `percent-encoding.workspace = true`

**验证**: `cargo test -p conduit-server --lib`,关注 heartbeat URL decode 集成测试 `heartbeat_query_url_decodes_special_chars_into_passive_record` 必须仍过。

### 阶段 3: P0-A — `control_api.rs` 双端改 axum

**新依赖**:
- workspace `Cargo.toml` 加:
  ```toml
  axum = { version = "0.7", default-features = false, features = ["http1", "json", "macros", "tokio"] }
  tower-http = { version = "0.5", default-features = false, features = ["cors"] }
  tokio-stream = "0.1"
  ```
- `server-app/src-tauri/Cargo.toml` + `client-app/src-tauri/Cargo.toml` 各加 `axum.workspace = true` / `tower-http.workspace = true` / `tokio-stream.workspace = true`

**server-app 改动**(`src/proxy/control_api.rs`):
1. **删除**: `handle_request` / `serve_*` 内的手写 HTTP 解析;`drain_headers` / `send_json_status` / `send_cors_preflight`(全部 helper)
2. **新结构**:
   ```rust
   pub async fn run(core: ProxyCore, cancel: CancellationToken) -> std::io::Result<()> {
       let app = Router::new()
           .route("/healthz", get(serve_healthz))
           .route("/api/status", get(serve_status))
           .route("/api/clients", get(serve_clients))
           .route("/api/traffic", get(serve_traffic))
           .route("/api/admin/stop", post(serve_admin_stop))
           .route("/api/events", get(serve_events))
           .layer(CorsLayer::permissive())
           .with_state(AppState { core, cancel: cancel.clone() });
       let listener = TcpListener::bind(format!("127.0.0.1:{}", core.config().api_port)).await?;
       axum::serve(listener, app).with_graceful_shutdown(async move { cancel.cancelled().await }).await
   }
   ```
3. **handler 改造**: 每个 `serve_*` 接 `State<AppState>` 直接返 `Json(SomeStruct)` 或 `(StatusCode, Json<...>)`,删除手写 status/header/body 拼装。结构体 `HealthzResponse` / `ServerStatusOut` / 等等保留(它们是 wire 契约)。
4. **SSE**: `serve_events` 改:
   ```rust
   async fn serve_events(State(s): State<AppState>) -> Sse<impl Stream<Item = Result<Event, Infallible>>> {
       let mut rx = s.core.event_bus().subscribe();
       let stream = async_stream::stream! { loop { match rx.recv().await { ... yield Event::default().event(kind).data(payload) ... } } };
       Sse::new(stream).keep_alive(KeepAlive::default())
   }
   ```
   或用 `tokio_stream::wrappers::BroadcastStream`(更简洁)。

**client-app 改动**(`src/proxy/control_api.rs`):
- 同样的 axum 改造模板。endpoints 较多(`/api/connection` / `/api/servers` / `/api/connect/{id}` / 等),逐个 handler 替换。
- 注意 path param 用 axum `Path<String>` 直接拿,不再手 split。

**验证**:
- `cargo test -p conduit-server -p conduit-client --lib --no-fail-fast` 全过
- 真机起 server-app, `curl http://127.0.0.1:<api_port>/healthz` / `/api/status` / `/api/clients` 返回结构 ≡ 改造前(用 jq 对 diff)
- 浏览器开 server-app UI 看 NetworkPanel / Dashboard / 流量图 / SSE 全正常

**风险点**:
- axum 0.7 + tokio 1.x 现有 workspace 已 OK
- CORS 行为(loopback only,Allow-Origin: *) tower-http `CorsLayer::permissive()` 等价

### 阶段 4: P1-6 — `security-framework` 收 Authorization Services FFI

**改动**:
1. `Cargo.toml` workspace 加 `security-framework = { version = "2.11", default-features = false }`(macOS 才用,但 client 已经做了 `cfg(target_os = "macos")`)
2. `client-app/src-tauri/Cargo.toml` 在 `[target.'cfg(target_os = "macos")'.dependencies]` 下加 `security-framework.workspace = true`
3. `client-app/src-tauri/src/proxy/system_proxy_sc.rs`:
   - 删 `extern "C" { fn AuthorizationCreate(...); fn AuthorizationFree(...); }`
   - 删 `K_AUTHORIZATION_FLAG_*` 常量
   - 改用 `security_framework::authorization::Authorization::new(...)?` 创建 token
   - 用 `auth.as_concrete_TypeRef() as AuthorizationRef` 喂给 `SCPreferencesCreateWithAuthorization`
   - `AuthHolder` 改成持有 `security_framework::authorization::Authorization`(它实现 Drop 即自动 free)
4. **保留** `system_configuration_sys` 那部分 FFI(还没有更高层封装)

**验证**:
- macOS 真机: 杀掉 client-app → 重启 → 第一次连 server 弹出原生密码框 → 点确定 → 之后 connect/disconnect 不再弹框 → kill 进程后 system_proxy 已被清理

**风险点**:
- security-framework 2.11 是 2026-04 release,改动小,API 稳。
- AuthorizationRef Drop 顺序: 必须在 SCPreferences 用完之后再 free,实际由 OnceLock 持有 → AuthHolder Drop 时 free,这一行为不变。

### 阶段 5: P0-B — `proxy/http.rs` forward proxy 改 hyper

**新依赖**(workspace `Cargo.toml`):
```toml
hyper = { version = "1", features = ["http1", "server", "client"] }
hyper-util = { version = "0.1", features = ["tokio", "server", "client", "client-legacy"] }
http-body-util = "0.1"
bytes = "1"
```
`server-app/src-tauri/Cargo.toml` 全部 `.workspace = true`

**改动**(`src/proxy/http.rs`):
1. **保留**: 所有路由分发判定逻辑、ACL(`is_client_allowed` / `is_connect_port_allowed`)、`SessionRegistry` 集成、`bidirectional_relay` 调用。
2. **替换**:
   - `read_request_line` / `parse_request_line` / `drain_headers` / `parse_authority` / `parse_absolute_uri` / `is_hop_by_hop_header` / `build_upstream_head` / `send_simple` 全删
   - `accept loop` 用 `hyper_util::server::conn::auto::Builder`(支持 HTTP/1.1 keep-alive)
   - `handle_connection` 拆成 `Service<Request<Incoming>>`:
     - `CONNECT host:port` → 用 hyper Upgrade API,upgrade 成功后拿 `Upgraded` → 转 `TokioIo` → 喂给 `bidirectional_relay`
     - absolute-URI(`http://...`)→ 用 `hyper_util::client::legacy::Client` 或 `reqwest` 发上游,流式回写响应
     - `GET /proxy.pac` / `/wpad.dat` → 直接构造 `Response::builder().header(...).body(Full::from(body))`
     - `GET /api/clients/heartbeat` / `GET /status` / `GET /check` → 同上
3. **`pending` buffer 处理**: 现有 `reunite_with_pending_buffer` 是给"absolute-URI 转发时 BufReader 残字节"用的,hyper 改造后由 hyper 自己接管 body 流,这块逻辑可以**整体删除**。
4. **测试**: 现有集成测试(`pac_endpoint_returns_template_with_substituted_host_port` 等)全部基于"socket 直发 HTTP/1.1 字节,read body 字符串匹配",hyper 化后请求/响应仍然是 HTTP/1.1 字节,**测试不需要重写**。

**验证**:
- `cargo test -p conduit-server --lib --no-fail-fast` 全过(尤其 `connect_tunnels_payload_to_upstream_echo_server` / `absolute_uri_get_is_forwarded_to_upstream_origin_form` / `absolute_uri_chunked_request_body_returns_501` / `connect_to_disallowed_port_returns_403`)
- 真机回归 3 类流量:
  1. CONNECT: 浏览器打开 server-app 提供的 PAC 后,访问 https://example.com(走 CONNECT 隧道)
  2. PAC: `curl http://<server>:<http_port>/proxy.pac` 返回正确 PAC,`__PROXY_HOST__` 已替换
  3. absolute-URI: `curl -x http://<server>:<http_port> http://httpbin.org/ip`(明文 HTTP 走 absolute URI)

**风险点**:
- hyper 1.x 的 CONNECT upgrade API 比 0.14 简单了不少,但 `Upgraded` → `bidirectional_relay` 的 `AsyncRead+AsyncWrite` 边界要小心: 用 `hyper_util::rt::TokioIo` 包一下即可。
- hyper Client(`hyper_util::client::legacy::Client<HttpConnector, Full<Bytes>>`)做 absolute-URI 转发时,要禁用 Connection: keep-alive 行为,确保和原 `Connection: close` 一致 — 用 `Client::builder().pool_max_idle_per_host(0)` 即可。

## 四、风险与回滚

| 阶段 | 主要风险 | 回滚成本 | 缓解策略 |
|-----|---------|---------|---------|
| 1 | 路径错误 | 低,1 个 commit revert | 阶段 1 工作量极小,先做无副作用 |
| 2 | percent-encoding 与原 url_decode 不同(对 `+` 处理等) | 低 | 原 url_decode 注释里写"`+` 保持原样",percent-encoding 也是这样;1 个 smoke 测保证 |
| 3 | axum SSE 与原手写 `event:\\ndata:\\n\\n` 帧格式差异 | 中,UI store 监听代码可能要小调 | 改完后断言 SSE 流字节级 ≡ 原格式;UI 不动 |
| 4 | macOS 弹密码框流程坏掉 = 不能切系统代理 | 中,真机可见 | 必须真机测,不能 skip |
| 5 | hyper CONNECT upgrade 出错 = 整个 forward proxy 不可用 | 高 | 阶段 5 单独成 commit,真机回归 3 类流量,任何一个不过则**回滚整个阶段**,先单独修 hyper 集成 |
