# Conduit 打包与发布说明

> 日期: 2026-05-03
> 范围: 把 server-app 与 client-app 从源码打成可分发的 .dmg / .msi / .deb;
>      并在 macOS 上跑通"双击安装→开箱即用"流程。
> 适用版本: v0.1.0
> 主要新增脚本: `scripts/build-sidecars.sh`, `scripts/release.sh`, `scripts/e2e.sh`

---

## 1. 总览

Conduit 由两层进程构成,需要分别打包再合并:

```
┌─────────────────────────────────────────┐
│  Conduit Server.app  (Tauri 主进程,Rust) │
│    └── conduit-server-sidecar  (Python)  │  ← PyInstaller 单文件
└─────────────────────────────────────────┘

┌─────────────────────────────────────────┐
│  Conduit Client.app  (Tauri 主进程,Rust) │
│    └── conduit-client-sidecar  (Python)  │  ← PyInstaller 单文件
└─────────────────────────────────────────┘
```

两层关系: Tauri 主进程在 `sidecar.rs` 里 spawn sidecar。Sidecar 做完所有
代理/路由/mDNS/HTTP API,Tauri 只管 UI 容器 + 系统集成 (托盘、自启、
窗口管理)。

**dev 模式 vs release 模式自动适配:**
- `pnpm dev:*` 时,sidecar.rs 找不到 binary,回退到 `python3 *.py`(走源码)。
- 安装的 .app 启动时,sidecar.rs 在 exe 同目录找到打包好的 binary,直接 exec。

## 2. 三个一键脚本

### 2.1 `scripts/build-sidecars.sh` —— 把 Python 打成单二进制

```bash
./scripts/build-sidecars.sh           # 同时打 server + client
./scripts/build-sidecars.sh server    # 只打 server
./scripts/build-sidecars.sh client    # 只打 client
```

输出:
- `server-app/src-tauri/binaries/conduit-server-sidecar-<triple>`
- `client-app/src-tauri/binaries/conduit-client-sidecar-<triple>`

`<triple>` 自动从当前平台推导 (Tauri externalBin 命名约定):
| 平台 | triple |
|---|---|
| macOS Apple Silicon | `aarch64-apple-darwin` |
| macOS Intel | `x86_64-apple-darwin` |
| Windows x64 | `x86_64-pc-windows-msvc` (产物加 `.exe`) |
| Linux x64 | `x86_64-unknown-linux-gnu` |

依赖:
- Python 3.10+
- PyInstaller >= 6.0 (脚本会按需自动 `pip install`)

体积参考 (PyInstaller --onefile,arm64):
- server sidecar: ≈ 27 MB
- client sidecar: ≈ 26 MB

不支持跨平台编译 —— 要发布 Win/Linux 必须在那台机器上跑。

### 2.2 `scripts/release.sh` —— 全流程打包

```bash
./scripts/release.sh           # 打 server + client
./scripts/release.sh server    # 只打 server
./scripts/release.sh client    # 只打 client
```

它顺序执行:
1. 跑 `build-sidecars.sh` 产 sidecar binary
2. `pnpm install` (确保前端依赖就绪)
3. 进入 `<app>/` 跑 `pnpm tauri build --config '{"bundle":{"externalBin":["binaries/conduit-<app>-sidecar"]}}'`
4. 把产物从 `<app>/src-tauri/target/release/bundle/<format>/` 归集到 `dist/<app>/`
5. (可选) 公证 `.dmg` —— 检测到 `APPLE_ID` 环境变量才会执行

注意: `--config` inline JSON 在 release 时**临时**注入 externalBin,这样
dev 时 `tauri.conf.json` 里没有这一项,cargo check 不会因为找不到 binary 而失败。

输出 (macOS):
```
dist/server/Conduit Server.app
dist/server/Conduit Server_0.1.0_aarch64.dmg
dist/client/Conduit Client.app
dist/client/Conduit Client_0.1.0_aarch64.dmg
```

### 2.3 `scripts/e2e.sh` —— 端到端冒烟测试

```bash
./scripts/e2e.sh           # 跑完后自动清理
./scripts/e2e.sh --keep    # 测完留 sidecar,方便手动 curl 调查
```

流程: spawn server + client → 等 healthz → 等 mDNS 发现 → POST connect
→ curl --socks5 跑 5 次 → 校验流量 / 缓存 / 心跳 / diagnose 全 OK
→ disconnect → 清理。

11 秒内全过即代表核心功能链路通。可加进 CI。

## 3. macOS 公证 (notarization)

未公证的 `.dmg` 用户首次双击会被 Gatekeeper 拦截,需要 Ctrl+Click → 打开 → 确认。
要走"普通双击安装",必须 Apple Developer 账号 + Notary 凭证。

### 3.1 准备

1. 注册 Apple Developer Program ($99/年)
2. 在 keychain 里安装 Developer ID Application 证书
3. 申请 app-specific password
4. 在 `tauri.conf.json` 的 `bundle.macOS` 里加 `signingIdentity`:
   ```json
   "macOS": {
     "signingIdentity": "Developer ID Application: <你的名字> (<TEAM_ID>)"
   }
   ```

### 3.2 跑 release.sh 时

```bash
APPLE_ID="you@example.com" \
APPLE_PASSWORD="xxxx-xxxx-xxxx-xxxx" \
APPLE_TEAM_ID="ABCD123456" \
./scripts/release.sh
```

`release.sh` 会自动检测这三个变量。当前实现里 notary 步骤是 TODO 注释 —— 待 Apple Developer
账号到位后取消注释即可。

### 3.3 验证公证状态

```bash
spctl -a -vv "dist/server/Conduit Server.app"
# accepted source=Notarized Developer ID
```

## 4. Windows 代码签名 (EV cert)

Windows Defender 对未签名的可执行文件会报 SmartScreen 警告。
要跳过此警告必须 EV (Extended Validation) 代码签名证书。

`release.sh` 留了 hook,但 v0.1 不强制做 —— 用户可手动绕过。

## 5. 安装流程 (用户视角)

### 5.1 macOS

```
1. 双击 Conduit Server.dmg
2. 把 Conduit Server.app 拖进 /Applications
3. 首次启动: 右键 → 打开 → 弹窗"无法验证开发者" → 点【打开】
   (公证完成后此步可省略)
4. 系统提示"Conduit Server 想要使用本地网络" → 允许
5. 系统提示"Conduit Server 想要修改系统代理" → (Server 不需要,可忽略)
6. 主窗口 → 自动启动 → 显示 HTTP/SOCKS5/API 端口 → 等待客户端
```

Client 类似,但第 5 步要允许,因为 client 默认会切系统代理。
若拒绝(或在 macOS 13+ 因没 admin 权限切换失败),客户端会**继续工作**,
只是顶部会出现琥珀色警告横幅,提示用户手动配 SOCKS5 主机和端口。

### 5.2 Windows / Linux

仅 server-app,client-app v0.1 不支持 (推到 v0.2)。

```
Windows: 双击 Conduit Server_0.1.0_x64-setup.exe
Linux:   sudo dpkg -i conduit-server_0.1.0_amd64.deb
```

## 6. 故障排除

### 6.1 sidecar 起不来

```bash
# 直接跑 release 后的 sidecar,看错误
./dist/server/Conduit\ Server.app/Contents/MacOS/conduit-server-sidecar --help
```

常见原因:
- macOS Gatekeeper 拦截二进制 → `xattr -dr com.apple.quarantine "Conduit Server.app"`
- PyInstaller bundle 里缺 hidden import → 在 `build-sidecars.sh` 加 `--hidden-import xxx`

### 6.2 mDNS 在某些环境不工作

- 公司 / 公共 WLAN 经常屏蔽 multicast
- macOS 14+ 需要在「系统设置 → 隐私与安全 → 本地网络」里允许 Conduit
- 解决: 在 client 的「设置」页手动添加 server IP+端口

### 6.3 client 顶部出现"系统代理未自动切换"横幅

正常,不影响代理工作。原因:
- macOS 13+ `networksetup -setsocksfirewallproxy` 需要管理员权限
- Conduit 默认不要求 sudo,所以走"提示用户手动配"路径

要消除横幅的两条路:
1. 用户手动在浏览器/系统配 SOCKS5 主机=127.0.0.1 端口=client 显示的端口
2. 以 sudo 启动 Conduit (不推荐,增大攻击面)

### 6.4 e2e.sh 失败

按 step 看错误:
- step 3 (healthz) 超时 → 看 `/tmp/conduit-e2e/{server,client}.log`
- step 4a (mDNS 没出) → 检查本地网络权限是否授权,或防火墙是否拦
- step 5 (流量 0) → client local_proxy 端口冲突可能;换端口重试
